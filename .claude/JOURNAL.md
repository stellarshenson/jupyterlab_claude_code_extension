10. **Task - Reuse only claude-running terminals** (v1.0.43): Stop activating bare bash terminals just because their cwd matches a project<br>
    **Result**: A JL terminal opened manually at a Claude Code project's cwd without claude running was being matched by `_findTerminalForCwd` and reactivated on row click, swallowing the resume. The reuse path matched on cwd alone, never on what was running. New `_tree_has_claude(root_pid)` in `jupyterlab_claude_code_extension/routes.py` walks the same tree as `_terminal_cwds` and returns True iff any pid has `_process_comm(pid) == "claude"`. `TerminalCwdHandler` now returns `{terminal_name, cwds, has_claude}`. Frontend `ITerminalCwdResponse` gains the boolean; `_findTerminalForCwd` skips candidates where `has_claude` is false, so a bash terminal is rejected and spawn flow runs. 11. **Task - stty waiter so claude renders at full width** (v1.0.44): Borrowed `_INIT_WAITER` from `../jupyterlab_basic_terminal_extension` to fix narrow TUI rendering<br>
    **Result**: When `LaunchClaudeTerminalHandler` spawned claude directly via `terminal_manager.create(shell_command=[claude, --resume, sid], cwd=...)`, claude painted its TUI before the JL WebSocket client had resized the pty - so the rendered window stayed at the pty's tiny default (~80×24) even after the tab visually grew. Brief race during waiter window (≤5 s) where `comm == "bash"` accepted as cost. Built v1.0.44 via `make install`, `enabled OK`.

12. **Task - Fix waiter that never waited** (v1.0.46): Replace the threshold-based `_INIT_WAITER` with a SIGWINCH-trap + size-change comparison<br>
    **Result**: The borrowed waiter from `jupyterlab_basic_terminal_extension` had `[ "$r" -ge 20 ] && [ "$c" -ge 80 ]`, which is a no-op because `terminado.NamedTermManager.new_terminal` defaults the pty to 24×80 - `c=80 >= 80` passes on iteration 1 and the loop exits without waiting for JL's WebSocket resize. Claude still painted at the default size. New `_INIT_WAITER` in `jupyterlab_claude_code_extension/routes.py` captures `R0`/`C0` via `stty size` at entry, installs `trap 'CHANGED=1' WINCH`, and loops until either the trap fires or `stty size` differs from the captured values - 5 s fallback unchanged. The kernel issues SIGWINCH on the first ioctl from the WebSocket client, so claude now waits for the real size to land. Left a `TODO_PTY_RESIZE_WAITER.md` in `../jupyterlab_basic_terminal_extension/` documenting the same bug and the fix. Built v1.0.46 via `make install`, `enabled OK`.
