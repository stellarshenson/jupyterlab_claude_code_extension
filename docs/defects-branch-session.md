### DEF-1: Branch name not applied at launch, false "use /rename" warning

- [x] the panel warned `name "..." could not be applied - use /rename` after a branch launch, yet a manual `/rename` worked; cause: `claude -n` owns the name (written on the fork's first turn) but the obsolete `sessions/set-title` poll 404'd for 30s on the not-yet-written fork file and fired a false failure; fix: removed the set-title path (frontend poll + warning, backend handler + route, `set_branch_title`, tests); `src/widget.ts`
  - 2026-06-21 reported: "Branched session started, but the name 'home-accessories' could not be applied - use /rename in the session -> and the rename was actually successful"
  - 2026-06-21 fixed: name owned solely by `claude -n`; jest 43 + pytest 79 green, adversarial review SHIP; see [acc-crit Branch Session](acc-crit-jupyterlab_claude_code_extension.md#branch-session)

### DEF-2: Branched session missing from panel until first turn

- [x] a new branch stayed out of the panel (even after a manual refresh), appearing only minutes later; cause: claude writes a forked session's `<forkId>.jsonl` lazily on its first turn, not at launch (proven: absent through 20s idle; claude refuses a pre-seeded id with "already in use"), and the panel only lists files that exist on disk; wontfix-external (claude limitation), mitigated by the forced-refresh spinner feedback; `src/widget.ts`
  - 2026-06-21 reported: "branched session initially did not show in panel, not even after refresh; only after few minutes appeared (with branch icon) on the workspace session"
  - 2026-06-21 resolved: root-caused as a claude limitation; mitigated by the forced refresh re-poll, see [acc-crit Panel Refresh](acc-crit-jupyterlab_claude_code_extension.md#panel-refresh)
  - 2026-06-22 improved: a bounded fast watcher (`_watchForBranch`, 2 s cadence) now polls for the fork file after launch and refreshes the row the second it materialises, so the gap is seconds not minutes; see [acc-crit Open Branched Conversation](acc-crit-jupyterlab_claude_code_extension.md#open-branched-conversation) "Fast refresh after fork"

### DEF-3: Switching a branch then clicking the row resumes the original conversation

- [x] after switching the row to another conversation, clicking the row landed back in the ORIGINAL conversation, not the switched branch; cause: terminal reuse was keyed purely by project cwd (`_terminalsByPath` + `_findTerminalForCwd` matched cwd + `has_claude` only), so the still-open terminal running `claude --resume <original>` was refocused regardless of which branch was now current - and a running claude process is pinned to one conversation for its life; fix: backend `terminal-cwd` now reports the running claude's conversation id (parsed from its argv - `--session-id` for a fork, else `--resume`), and reuse only refocuses a terminal running the SAME conversation; a known-different one is left alone and a new terminal is launched on the wanted branch; `jupyterlab_claude_code_extension/routes.py`, `src/widget.ts`
  - 2026-06-22 reported: "why switched to another branch of the session - and clicking, I am getting to the original session, not the branch?"
  - 2026-06-22 fixed: conversation-aware reuse (lenient for the row's current, strict for Open Branched Conversation); the new "Open Branched Conversation" submenu + popup Open let branches be opened directly and independently; jest 55 + pytest 87 green, Galata UI tests added; see [acc-crit Open Branched Conversation](acc-crit-jupyterlab_claude_code_extension.md#open-branched-conversation)
  - 2026-06-22 regressed (DEF-4): the v1.2.26 "lenient for the row's current" branch still reused a cwd-matching terminal whose conversation was UNKNOWN, refocusing the wrong conversation - superseded by the strict-on-identity rule in DEF-4

### DEF-4: Switched branch row focuses an unidentified terminal running another conversation

HIGH - lands the user in the wrong conversation.

- [x] after switching the row to another branch, clicking the row focuses a still-open terminal running a DIFFERENT conversation (the original), not the switched branch; only after that terminal is closed does the click open the branch; cause: lenient row-click reuse (the `!strict && unknownConversation` branch in `_doResumeInTerminal`'s microcache and in `_findTerminalForCwd`) refocuses ANY cwd-matching claude terminal whose conversation id is unknown (`session_id: null`) - a claude started with `-c`/`--continue` or a bare `claude` (no `--resume`/`--session-id`) reports null, so the unidentified terminal is taken as a match; fix: reuse only on a positive conversation-id match (drop the lenient unknown-reuse, the `strict` flag goes with it), and make every extension launch identifiable so its terminal is never unknown - New Session now passes a frontend-generated `--session-id <uuid>` (new `new_session_id` launch param, verified claude starts a fresh session with it); `src/widget.ts`, `jupyterlab_claude_code_extension/routes.py`

### DEF-5: Switched branch reverts to the most-active conversation on refresh

- [x] after switching the row to another branch, the panel reverts the row's current back to the original conversation after a refresh; cause: `switch_branch` persists the choice only by touching the chosen JSONL's mtime and `_resolve_latest` ranks by newest mtime - continuing to work in the original conversation appends to its JSONL, bumping its mtime above the switched branch, so the next 30s poll re-resolves current back to it; fix: `switch_branch` writes a durable per-project pin (`.jl-current` sidecar holding the chosen session id) and `_resolve_latest` honours the pin over recency when the pinned JSONL exists and its cwd is project-consistent; a dangling/cwd-foreign/corrupt pin is ignored and recency resumes; `jupyterlab_claude_code_extension/sessions.py`
  - 2026-06-22 reported: "also after some time switches back to 'workspace' (from workspace-fix) - why?"; user diagnosis: engaging the original conversation makes the panel follow it (recency), overriding the explicit switch
  - 2026-06-22 fixed: durable `.jl-current` pin (written only for cwd-consistent branches, so a failed switch never clobbers a prior valid pin); a new session clears the pin so recency resumes (the adversarial review caught the pin otherwise stranding a fresh session behind the old branch); `_read_current_pin` ignores corrupt/non-UTF-8 content that would otherwise crash listing; pytest 98 green, review SHIP; see [acc-crit Branch Switching](acc-crit-jupyterlab_claude_code_extension.md#branch-switching) "Sticky switch"
  - 2026-06-22 verified live: against the restarted server's API on a throwaway project, `sessions/switch` to the older conversation wrote `.jl-current` and made it current; bumping the other conversation's mtime far newer (simulating activity) did NOT revert it - the pin held, the recency-revert is gone

### DEF-6: Created branch appears but is not made the row's current conversation

- [x] a freshly created named branch, once its JSONL materialises, shows in the panel but the row's current stays the PARENT it was forked from, not the new branch; cause: branch creation relied on recency to make the fork current ("the forked JSONL is the newest"), but the parent is the conversation the user is actively in, so it keeps being appended and its mtime overtakes the fork's - `_resolve_latest` then re-picks the parent; fix: the fork launch writes the durable `.jl-current` pin to the fork id (new `set_current_pin`, symmetric with `switch_branch` and the inverse of a new session's `clear_current_pin`), so `_resolve_latest` honours the fork over recency the moment its JSONL exists; the pin is dangling and harmless until then; `jupyterlab_claude_code_extension/routes.py`, `jupyterlab_claude_code_extension/sessions.py`
  - 2026-06-23 reported: "started a branched session from workspace, haven't submitted any message yet; over 2m passed - still no branch icon and no new branch (delava-stuff)"; refined: "after first message the session appears, but wasn't switched to; in the past a branched session appeared right away"; intended behaviour - a created branch opens, becomes primary, shows the branch icon; a switch makes the switched one primary; writing in a non-primary conversation does not auto-promote it
  - 2026-06-23 evidenced: live `pgrep` showed the fork alive 4m24s (`--fork-session --session-id 8dc84140... -n delava-stuff`, cwd `/home/lab/workspace`) yet `8dc84140*.jsonl` was absent everywhere under `~/.claude/projects` - confirming claude writes the fork JSONL only on its first turn (the pre-first-turn invisibility is the known external limitation, DEF-2; the fast watcher cannot find a file that does not exist)
  - 2026-06-23 fixed: `set_current_pin` written at fork launch makes the branch primary once it materialises, even while the parent stays most-active; the durable pin reuses the DEF-5 mechanism and is benign if the fork is abandoned (dangling pin ignored, cleared by the next new session, overwritten by the next switch); pytest 102 + jest 58 green; see [acc-crit Branch Session](acc-crit-jupyterlab_claude_code_extension.md#branch-session) "Becomes current" and "Edge: parent stays active after a fork"
  - 2026-06-23 not fixed (external): the branch still cannot appear BEFORE the first turn - no JSONL exists to list; this is DEF-2's claude limitation, unchanged
